# UGUI 引用与事件生成器

通过 `Tool/UGUI Script Generator` 打开窗口，将控件拖入窗口任意位置即可添加，支持批量拖入。拖入 GameObject 时自动推荐组件类型，直接拖入组件时使用该组件类型，同一对象同一类型会跳过重复添加。已有面板请使用根节点右键菜单 `工具/Generate UI Script for UIPanel`，恢复已有引用和监听配置。根节点仍需以 `UIPanel` 结尾。

也可以直接在 Hierarchy 中选中控件：Inspector 顶部会显示始终展开的“UI 引用”区域，支持添加引用、替换对象、移除引用，以及直接勾选组件的监听事件。已绑定对象在 Hierarchy 右侧显示 `UI` 标记，悬停可查看字段和监听。无需给控件额外挂载组件。

窗口与 Inspector 共用同一份配置，编辑后立即保存。监听或引用列表变化后，点击“更新生成代码”生成对应字段、绑定及缺失回调；同类型引用对象的替换会直接更新面板上的序列化引用。点击“查看全部 UI 引用”，可在配置 asset 的 Inspector 中平铺编辑整个面板的引用，不需要展开列表。未赋值的引用会保留，并在生成时提示处理。

每条引用右侧的“监听”下拉菜单可以勾选多个事件，也可以选择“不监听”。菜单反射所选组件公开的 UnityEvent 字段和属性，例如 Button 的 `onClick`、Slider 的 `onValueChanged`、InputField 的 `onEndEdit`，以及 TMP 输入框的选择、提交等事件。参数类型随事件签名生成。EventSystem 的接口方法（如 PointerDown）不属于 UnityEvent，不会自动列入。

生成文件：

- `面板名.View.cs`：引用字段，每次重新生成。
- `面板名.Bind.cs`：仅包含监听注册、解绑等自动代码，每次重新生成。请勿在此文件写业务逻辑。
- `面板名.cs`：包含生命周期、回调方法及所有自定义逻辑。首次生成骨架，后续仅在主类末尾追加缺失的回调方法，保留已有内容及其位置。
- `Editor/面板名.UIBindings.asset`：编辑器配置，保存引用 GUID、固定字段名、对象标识、事件选择和固定回调名。应与生成的脚本及 `.meta` 一起提交版本管理。

GUID 是引用的稳定身份。控件名称只用于首次创建可读的字段名与方法名，之后修改 GameObject 名称不会改动既有字段或回调。这里不需要 Addressables，也不会在运行时按字符串查找或反射调用；生成的代码直接通过序列化引用注册和移除监听。

GUID 只保存在配置中，不拼入回调名。新回调使用 `字段名_事件名`，例如 `CheckBtn_Button_onClick`；确实重名时才追加 `_2`、`_3`。引用字段优先使用 `Button`、`TextMeshProUGUI` 等短类型名，并自动补充 using；存在同名类型冲突时才使用完整类型名。回调参数中的基础类型使用 `bool`、`float`、`int` 等 C# 关键字。

三个脚本使用同一个 `partial class`，因此 `.Bind.cs` 能直接访问主 `.cs` 中的私有回调，无需使用 `partial method`。

新增回调的默认位置是主类结束大括号之前。你可以将它移动到主 `.cs` 的任意业务 region，生成器会检查同目录中的方法声明，找到实现后就不再插入。主业务文件无需保留固定的回调 region 标记。定位主类时会忽略注释、字符、普通字符串及插值字符串中的大括号；无法明确定位时停止写入。

旧面板首次重新生成时会创建配置，并保留 Button/Toggle 原有的 `字段名Callback` 方法名。旧 `.Bind.cs` 中的回调、其他手写成员及 using 会迁入主 `.cs`，随后 `.Bind.cs` 转为纯自动代码。如果旧绑定文件包含额外类型或类型属性，生成器会停止并提示先将这些内容移入业务文件。

以后新增控件或监听都会补齐回调。取消监听仅移除注册，保留回调方法及其映射；重新勾选会复用它们。移除引用也会保留历史配置和回调，避免丢失业务逻辑。手动改 C# 字段名、回调名或组件类型仍需同步修改配置。

编辑器代码按职责拆分：`Window` 负责窗口交互，`Context` 与 `Loading` 负责编辑状态和收集引用，`Storage` 负责配置存取，`Validation` 负责冲突校验，`Generation` 与 `Templates` 负责生成流程和代码内容，`PendingApplier` 负责编译后赋值；`UGUIBindingInspector`、`UGUIBindingInspectorGUI` 与 `UGUIBindingHierarchy` 提供外部编辑入口。组件事件反射和 C# 文本编辑仍分别由 `Events`、`Source` 负责。
